# AI-дизайнер презентаций от команды DesignFactor

Сервис, который собирает готовую презентацию **в стиле произвольного шаблона**
по текстовому описанию задачи. На вход — `.pptx`-шаблон (или любая презентация
как ориентир по стилю) и бриф; на выход — три варианта готовой презентации на
макетах и в дизайн-системе этого шаблона, с нативными графиками и таблицами,
аудитом качества и экспортом в `pptx` / `pdf` / `html`. Ручное редактирование
результата не требуется.

Рабочая версия: **http://46.243.211.184/** (десктоп).

Репозиторий на сорскрафте: https://sourcecraft.dev/lct-hackaton-2026/case-14-ai-presentation-designer-team-10?rev=main

---

## Что делает сервис

1. **Постановка задачи.** Пользователь описывает презентацию своими словами
   (для кого, о чём, какой тон), при необходимости уточняет сценарий, аудиторию,
   тон изложения и диапазон числа слайдов и прикладывает презентацию-ориентир.
2. **Анализ шаблона.** Из `.pptx` извлекаются дизайн-система (палитра,
   гарнитуры, типографическая шкала, стили таблиц и графиков), все макеты
   с их ролями и слайды-образцы с распознанными видами композиций. Результат
   показывается пользователю в панели «Дизайн-система шаблона».
3. **План содержания.** Модель составляет структуру презентации: заголовок,
   назначение и содержимое каждого слайда — тезисы, текст, данные для графиков
   и таблиц. План открывается в панели «План содержания».
4. **Три варианта оформления.** По одному плану собираются три презентации
   разной плотности, характера и длины — Лаконичный и Сбалансированный без
   слайдов-разделителей, Насыщенный с разделителями смысловых частей
   (колода длиннее). Пользователь сравнивает их колонками или «слайд за
   слайдом» и выбирает один.
5. **Аудит качества (опционально).** Выбранный вариант проверяется по
   чек-листу Приложения 1: выход за границы, наложения, переполнение текста,
   отклонения от шрифтов/кеглей/палитры шаблона, плотность, заглушки,
   пустые слайды, а также содержательная проверка VLM. Замечания показываются
   рамками поверх превью слайдов; исправимые устраняются по клику.
6. **Доработка и экспорт.** Любой слайд можно пересобрать точечно — взять
   другую компоновку из шаблона, переписать текст или перенести слайд из
   другого варианта — и скачать результат в `pptx`, `pdf` или `html`.

## Соответствие задаче

| Требование | Как реализовано |
|---|---|
| Анализировать шаблоны: структуру, дизайн-систему, типовые паттерны слайдов | Парсер разбирает мастер, макеты и слайды `.pptx` в Template JSON и `DesignManifest`; распознаются роли макетов и виды композиций слайдов-образцов (обложка, карточки, метрики, таймлайн, тезис, галерея, финал и др.), извлекаются палитра, гарнитуры, шкала кеглей, стили таблиц и графиков |
| Понимать логику использования разных типов слайдов | Драматургия: план содержания размечается ролями (обложка, оглавление, раздел, тезисы, данные, финал) и под каждую роль подбирается композиция из распознанных в шаблоне; у трёх вариантов разные предпочтения и правило «не повторять одну композицию на одном слайде» |
| Подобрать паттерн под новый контент | Композиции оцениваются по числу тезисов, наличию данных и изображений; повторяемые блоки клонируются и подстраиваются под число тезисов (компоновки с лишними пустыми плашками штрафуются), таблицы и графики строятся нативными объектами PowerPoint в стилях шаблона |
| Адаптироваться к разным стилям оформления | Дизайн берётся оттуда, где он есть в конкретном шаблоне: из макетов, из слайдов-образцов, из обоих (`mixed`) — а если в шаблоне нет ни того, ни другого, из собственной библиотеки компоновок, раскрашенной шрифтами и цветами шаблона. Ничего не зашито под конкретный шаблон |
| Готовый результат без ручного редактирования | Подгонка текста в рамки при рендере, стилизация графиков под тёмный/светлый фон, аудит с автоисправлением, точечная доработка слайдов внутри сервиса, экспорт в трёх форматах |
| Полноценный AI-пайплайн, а не промпт | Детерминированный парсинг документов и извлечение структуры, LLM-оркестрация планирования и переформулировок, VLM для содержательного аудита, промпты и конфигурация — файлами (`backend/skills/*.yaml`, `pptx_template_parser_generator/prompts/*.txt`), ни одного текста промпта в коде |

## Как это устроено

```
Шаблон (.pptx) ─▶ Парсер ─▶ DesignManifest + Template JSON ─┐
                                                            ├─▶ Сборка A/B/C ─▶ Выбор ─▶ Аудит ─▶ Доработка ─▶ Экспорт
Бриф + назначение ─▶ Контент-агент (LLM) ─▶ ContentPlan ────┤
                     Драматургия ─▶ роли слайдов + композиции ┘
```

- **Парсер шаблона** (`pptx_template_parser_generator/`, `backend/app/pipeline/parser.py`,
  `sample_slides.py`, `design_system.py`) — Template JSON со всеми макетами и
  плейсхолдерами, слайды-образцы с разбором на повторяемые блоки, дизайн-система
  для интерфейса.
- **Контент-агент** (`backend/app/pipeline/content_agent.py`) — LLM по
  OpenAI-совместимому API составляет `ContentPlan`: слайды с назначением,
  заголовком и блоками (тезисы, текст, график, таблица). Промпт — файл
  `backend/skills/content_planning.yaml`.
- **Драматургия и сборка** (`dramaturgy.py`, `template_engine.py`, `slide_clone.py`,
  `library.py`, `styling.py`) — структурирование плана (промпт
  `backend/skills/content_structuring.yaml`), выбор композиций под три профиля
  плотности, клонирование образцов, библиотечные компоновки, нативные
  графики/таблицы, подгонка текста, стилизация под фон слайда.
- **Аудит** (`audit.py`, `audit_fix.py`, `audit_overlay.py`) — детерминированные
  проверки по Приложению 1 плюс VLM-вопросы к каждому слайду; карта замечаний
  с координатами фигур; точечные исправления и повторный аудит.
- **Оркестратор и API** (`orchestrator.py`, `api/routes.py`) — статусы задачи
  `queued → parsing → planning → assembling → awaiting_variant_choice →
  awaiting_audit_choice → auditing → done`, доработка слайдов, экспорт через
  LibreOffice.
- **Интерфейс** (`frontend/index.html`) — один статический файл: главная с
  постановкой задачи, таймлайн пайплайна, панели дизайн-системы и плана
  содержания, выбор варианта с режимом «слайд за слайдом», карта аудита,
  доработка слайдов, экспорт.

## Как развернуть и запустить

Решение — один Python-процесс (FastAPI), который отдаёт и API, и интерфейс.
Внешние зависимости: LibreOffice (превью слайдов и экспорт в pdf/html),
poppler (растеризация превью) и доступ к OpenAI-совместимому LLM-эндпоинту.

### 1. Системные зависимости

Ubuntu / Debian:

```bash
sudo apt-get update
sudo apt-get install -y python3 python3-venv python3-pip \
    libreoffice-impress poppler-utils \
    fonts-dejavu fonts-liberation fonts-crosextra-carlito fonts-noto-core
```

macOS (Homebrew): `brew install python@3.12 poppler && brew install --cask libreoffice`.

Проверка: `soffice --version` и `pdftoppm -v` должны отвечать. Python 3.11+
(проверено на 3.12).

### 2. Backend

```bash
git clone <url-репозитория> designfactor && cd designfactor/backend
python3 -m venv venv
venv/bin/pip install -r requirements.txt
cp .env.example .env
```

В `.env` укажите LLM-эндпоинт (любой OpenAI-совместимый: vLLM, Ollama,
llama.cpp server, OpenRouter, облачные шлюзы). На проде используется
Qwen3.8-27B — см. [MODELS.md](MODELS.md).

### Переменные окружения

Читаются `backend/app/config.py` (pydantic-settings) из `backend/.env`;
всё необязательно — у каждой есть значение по умолчанию.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `LLM_BASE_URL` | `http://localhost:11434/v1` | OpenAI-совместимый эндпоинт текстовой модели (план содержания, структурирование тезисов, переписывание, правки по аудиту) |
| `LLM_MODEL_NAME` | `gpt-4o-mini` | идентификатор модели у провайдера; прод — `qwen/qwen3.8-27b` |
| `LLM_API_KEY` | пусто | ключ; пусто — заголовок `Authorization` не отправляется (локальные Ollama/vLLM) |
| `LLM_PLANNING_TIMEOUT_S` | `120` | общий дедлайн вызова LLM на этапе планирования, с (включая повторы); при «Превышен общий дедлайн LLM» — 180 |
| `LLM_AUDIT_FIX_TIMEOUT_S` | `45` | дедлайн LLM-правок по результатам аудита, с |
| `VLM_BASE_URL` | `http://localhost:11434/v1` | эндпоинт vision-модели для «Валидации контента»; можно указать те же значения, что для LLM, если модель понимает картинки |
| `VLM_MODEL_NAME` | `gpt-4o-mini` | идентификатор VLM |
| `VLM_API_KEY` | пусто | ключ VLM |
| `VLM_AUDIT_ENABLED` | `true` | `false` — только детерминированный аудит, VLM не нужна |
| `STORAGE_DIR` | `storage` | каталог артефактов: `templates/` (загруженные шаблоны), `outputs/<job>/` (Template JSON, планы, `.pptx` вариантов, превью) |
| `SKILLS_DIR` | `skills` | каталог скиллов — yaml-файлов с промптами и параметрами агентов |

Пример `backend/.env` для прода:

```
LLM_BASE_URL=https://api.alltokens.ru/api/v1
LLM_MODEL_NAME=qwen/qwen3.8-27b
LLM_API_KEY=...
LLM_PLANNING_TIMEOUT_S=120
VLM_BASE_URL=https://api.alltokens.ru/api/v1
VLM_MODEL_NAME=qwen/qwen3.8-27b
VLM_API_KEY=...
VLM_AUDIT_ENABLED=true
```

Запуск:

```bash
venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8811
```

Откройте **http://127.0.0.1:8811/** — интерфейс раздаётся тем же процессом из
папки `frontend/`. Документация API: http://127.0.0.1:8811/docs.

### 3. Проверка работы

Через интерфейс: приложите `.pptx`-шаблон кнопкой «+», опишите задачу,
нажмите «→». Полный цикл до трёх вариантов занимает 1,5–3 минуты в
зависимости от скорости LLM; далее — выбор варианта, аудит (или «пропустить»),
экспорт.

Через API (без интерфейса):

```bash
JOB=$(curl -s -X POST http://127.0.0.1:8811/jobs \
  -F template=@template.pptx \
  -F brief="Итоги года: рост аудитории, новые продукты, план на следующий год" \
  -F purpose="Отчёт для руководства" -F slide_count=8 -F slide_count_max=10 \
  | python3 -c "import sys,json;print(json.load(sys.stdin)['job_id'])")
curl -s http://127.0.0.1:8811/jobs/$JOB | python3 -m json.tool | grep '"status"'
# дождитесь awaiting_variant_choice, затем:
curl -o result.pptx "http://127.0.0.1:8811/jobs/$JOB/export?format=pptx&variant=variant_b"
```

### 4. Продуктивный контур (как развёрнута рабочая версия)

- `systemd`-сервис запускает `venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8811`
  из `backend/`.
- nginx раздаёт `frontend/` как статику и проксирует на `127.0.0.1:8811`
  пути `/jobs`, `/templates`, `/excel`, `/docs`, `/openapi.json`;
  `client_max_body_size 200M` для крупных шаблонов.
- Интерфейс ходит в API того же origin; для другого адреса API можно задать
  `localStorage.df_api_base` в консоли браузера.

### 5. Если что-то не так

| Симптом | Причина и действие |
|---|---|
| Превью слайдов не появляются, экспорт pdf/html падает | Нет `soffice` или `pdftoppm` в `PATH` — установите LibreOffice и poppler-utils |
| В логах «Превышен общий дедлайн LLM» | Медленный эндпоинт — поднимите `LLM_PLANNING_TIMEOUT_S` до 180 |
| Аудит помечает содержательные проверки как невыполненные | VLM недоступна — задайте `VLM_*` или выключите `VLM_AUDIT_ENABLED=false` |
| Шрифты в превью отличаются от PowerPoint | Установите гарнитуры шаблона в систему; экспортируемый `.pptx` шрифты не теряет |
| Задачи исчезли после перезапуска | Хранилище задач — в памяти процесса (осознанное упрощение прототипа) |

## Ограничения текущей версии

- **Хранилище задач — в памяти процесса.** Артефакты (`.pptx`, планы, превью)
  лежат на диске в `STORAGE_DIR`, но список задач и их статусы теряются при
  перезапуске backend; интерфейс помнит последнюю задачу в `localStorage`.
  Осознанное упрощение прототипа: монолит без БД и очередей.
- **Один процесс, без воркеров.** Каждая задача — `asyncio`-таск; сборка трёх
  вариантов идёт в thread-pool. Параллельная нагрузка ограничена одним
  процессом; на 2 vCPU / 2 GB полный цикл до трёх вариантов ≈ 1,5–3 мин,
  из них большая часть — ожидание LLM.
- **LibreOffice — внешняя зависимость.** Превью, PDF, HTML и PNG для VLM-аудита
  требуют `soffice` и `pdftoppm`; запуски сериализованы глобальным замком
  (параллельные конвертации роняли soffice). Превью может отличаться шрифтами
  от PowerPoint, если гарнитуры шаблона не установлены в системе.
- **HTML-экспорт — автономная страница-слайдшоу** со встроенными растрами
  слайдов, а не редактируемая разметка: штатный HTML-фильтр LibreOffice
  падает на шаблонах с крупными фото.
- **Аудит частично эвристический.** Переполнение текста оценивается без
  реального рендера шрифта; контраст считается только для явно заданных
  цветов; верхняя граница заполненности слайда откалибрована до 92 % вместо
  буквальных 75 % — обоснование в [AUDIT.md](AUDIT.md). VLM-вопросы 4, 9 и 11
  переформулированы под однослайдовый вызов.
- **Шаблоны без слотов заголовка** (авторские слайды с текстовыми блоками
  без плейсхолдеров) собираются целиком из библиотеки компоновок на
  шрифтах и цветах шаблона: фото и декор таких слайдов в результат не
  переносятся.
- **Не для продакшена «как есть».** CORS открыт на все origin, авторизации
  нет, загрузка шаблонов не ограничена по числу; перед реальным деплоем это
  нужно закрыть.
- **Только десктоп.** Интерфейс не адаптирован под мобильные экраны — по ТЗ.
- **Модель.** Качество плана содержания зависит от LLM; при недоступной
  модели задача завершается ошибкой, все остальные модельные шаги имеют
  детерминированные запасные варианты (см. [MODELS.md](MODELS.md)).
