# Локальный запуск в Docker

Нужны Docker Desktop в режиме Linux containers и Docker Compose 2.24+.
Из корня проекта:

```bash
docker compose up -d --build --wait
```

Интерфейс: http://localhost:3000/ · API: http://localhost:3000/docs

Контейнер содержит FastAPI, frontend, движок PPTX, LibreOffice, Poppler и шрифты.
Порт доступен только на 127.0.0.1. Приложение работает от пользователя app.
Первый build скачивает системные и Python-зависимости. GPU не требуется.

## Модель

Для генерации нужен OpenAI-совместимый LLM endpoint. Ключи не входят в образ.
При наличии `backend/.env` Compose передаёт его настройки в контейнер.
Если файла ещё нет, скопируйте `backend/.env.example`, затем задайте модель,
`LLM_BASE_URL`, `LLM_MODEL_NAME`, `LLM_API_KEY` и при необходимости `VLM_*`.
Существующий `.env` не перезаписывайте.

Для модели на Windows-хосте используйте `http://host.docker.internal:11434/v1`.
`localhost` внутри контейнера обозначает сам контейнер. Без `.env` образ использует
адрес `host.docker.internal`; имя модели нужно согласовать с вашим сервером.
Для облачного API используйте его HTTPS URL. VLM нужна только для соответствующего аудита.

Интерфейс и извлечение таблиц DOCX доступны без работающей модели. В этом случае
вместо LLM-сводки показываются заголовки с явным сообщением. Для планирования модель обязательна.

После изменения настроек:

```bash
docker compose up -d --force-recreate --wait
```

## Материалы

DOCX обрабатывается структурно: текст, описания таблиц и их ID, точные ячейки отдельно.
Простые таблицы до 6 строк данных × 5 столбцов можно выбрать в плане и перенести
в PPTX без переписывания чисел моделью. Подробности: `backend/docs/DOCX_TABLES.md`.
XLSX и PDF в обычной форме загрузки пока превращаются в текст; PDF использует
`pdftotext`, без OCR. Не подключённый расширенный Docling-путь не входит в образ:
PyTorch, RapidOCR и скачивание их моделей не нужны для действующего интерфейса.

## Управление и хранение

```bash
docker compose ps
docker compose logs -f --tail=100 app
docker compose stop
docker compose start
docker compose up -d --build --wait
```

Volume `designfactor_storage` хранит DOCX, реестры таблиц, PPTX и превью между
перезапусками. `docker compose down` его сохраняет. Команда с `-v` удаляет данные.
Задачи и анализы шаблонов хранятся в памяти; после перезапуска их нужно создать заново.
Поэтому используется один worker. Пользовательские шрифты для рендера нужно
добавлять в образ отдельно, если их нет среди установленных.
