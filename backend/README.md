# Цифровой дизайнер презентаций

Backend-монолит: генерация .pptx-презентации по шаблону дизайна и текстовому
брифу. Python + FastAPI, один процесс, весь пайплайн выполняется в одном
asyncio-таске — без микросервисов и без Celery/Redis.

Frontend (Next.js) в этом репозитории не разрабатывается — добавляется
отдельно.


## Стек

- Python 3.11+, FastAPI, uvicorn
- python-pptx — детерминированный парсинг шаблона и сборка .pptx нативными объектами
- Pydantic v2 / pydantic-settings — контракты данных и конфиг
- httpx — тонкий клиент к OpenAI-совместимому LLM/VLM endpoint
- PyYAML — промпты вынесены в backend/skills/*.yaml
- LibreOffice (soffice, внешняя зависимость) — конвертация .pptx в .pdf/.html



## API

- `POST /jobs` (multipart: `template` — .pptx-файл, `brief`, `purpose`) — создаёт
  задачу, сразу возвращает `job_id`, генерация идёт в фоне.
- `GET /jobs/{job_id}` — статус и все накопленные данные задачи (`design_manifest`,
  `content_plan`, `audit_issues`, ...).
- `POST /jobs/{job_id}/fix` (JSON: `{"issue_ids": [...]}`) — перезапускает
  Компоновщик и Аудит.
- `GET /jobs/{job_id}/export?format=pptx|pdf|html` — отдаёт готовый файл.

## Архитектура пайплайна

```
Шаблон (.pptx) ──▶ Парсер ──▶ DesignManifest ─┐
                                                ├─▶ Компоновщик ──▶ .pptx ──▶ Пайплайн проверки ──▶ Экспортёр
Бриф + назначение ──▶ Контент-агент ──▶ ContentPlan ─┘
```

Оркестратор (`app/orchestrator.py`) ведёт `Job` через
`queued → parsing → planning → assembling → auditing → done/failed`.

Подробности — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md),
[docs/MODELS.md](docs/MODELS.md), [docs/AUDIT.md](docs/AUDIT.md).

## Ограничения текущей версии

- **Нет БД.** Job-стор — `dict` в памяти процесса (`app/job_store.py`). Рестарт
  backend теряет все задачи.
- **Нет очередей/воркеров.** Каждый job — это `asyncio.create_task` в том же
  процессе. Параллельная нагрузка ограничена ресурсами одного процесса;
  осознанное упрощение MVP под требование "монолит без Celery/Redis".
- **Классификация макетов через VLM не реализована** — `parser.classify_layouts_with_vlm`
  это `NotImplementedError`-заглушка. Сейчас все роли макета определяются
  только детерминированно по типам плейсхолдеров из XML.
- **VLM-аудит контента реализован, но не проверен вживую.**
  `audit.audit_content_with_vlm` работает и вызывается автоматически при
  сборке каждого варианта (управляется флагом `VLM_AUDIT_ENABLED` в
  `config.py`), но в текущей среде разработки нет доступа к реальному
  VLM-эндпоинту — подтверждена только graceful degradation (при
  недоступности VLM создаётся одна явная проблема на слайд вместо падения
  пайплайна). Подробности и полный список 11 вопросов — в
  [docs/AUDIT.md](docs/AUDIT.md).
- **Реализованы все три варианта вёрстки** (`variant_a`/`variant_b`/`variant_c`)
  через генеративный движок паттернов вёрстки (отдельный YAML-конфиг,
  ~15-20 паттернов) — не заглушки.
- **`POST /jobs/{id}/fix` не применяет исправления точечно.** Он полностью
  пересобирает колоду и гоняет аудит заново — переданный список `issue_ids`
  сейчас только валидируется (что все id существуют), но не используется для
  избирательного авто-фикса конкретных проблем (например, обрезки буллетов).
- **Проверка контраста в аудите — best-effort.** Считается только когда и
  текст, и фон слайда имеют явно заданный `srgbClr` (не унаследованный из
  темы цвет) — иначе слайд молча пропускается, чтобы не давать ложных
  срабатываний. Порог зафиксирован на 4.5:1 согласно ТЗ.
- **Верхняя граница проверки заполненности слайда (аудит) откалибрована с
  75% (буквальный текст ТЗ) до 92%** — обоснование в [docs/AUDIT.md](docs/AUDIT.md#отклонения-от-буквального-текста-тз-с-обоснованием).
- **CORS открыт на `*`.** Перед реальным (не хакатонным) деплоем нужно сузить
  `allow_origins` в `app/main.py`.
- **Экспорт в pdf/html требует LibreOffice** как внешнюю системную
  зависимость — она не ставится через `requirements.txt`.
