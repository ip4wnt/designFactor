# AI-дизайнер презентаций (команда DesignFactor) — backend

Backend-монолит: генерация трёх вариантов .pptx-презентации по шаблону дизайна и
текстовому брифу. Python + FastAPI, один процесс, весь пайплайн задачи
выполняется в одном asyncio-таске — без микросервисов и без Celery/Redis.

Frontend — один статический файл `frontend/index.html` (десктоп), ходит в API
того же домена. Backend сам раздаёт папку `../frontend` с корня (`/`), поэтому
локально достаточно одного процесса uvicorn; в проде nginx раздаёт статику и
проксирует `/templates`, `/jobs`, `/excel`, `/docs`.


## Стек

- Python 3.11+ (проверено на 3.12), FastAPI, uvicorn
- python-pptx — разбор шаблона, нативные графики/таблицы, пост-обработка
- `pptx_template_parser_generator/` — общий движок команды: Template JSON,
  планировщик макетов (outline → copy → fill → repair), генератор
  презентации на макетах шаблона
- Pydantic v2 / pydantic-settings — контракты данных и конфиг
- openai/httpx — клиент к OpenAI-совместимому LLM/VLM endpoint
- Pillow, segno — превью и QR-коды
- LibreOffice (`soffice`) и poppler (`pdftoppm`) — системные зависимости:
  превью слайдов, экспорт pdf/html


## Запуск

```bash
cd backend
python -m venv venv && venv/bin/pip install -r requirements.txt
cp .env.example .env   # LLM_BASE_URL / LLM_MODEL_NAME / LLM_API_KEY (+ VLM_*, LLM_PLANNING_TIMEOUT_S)
venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8811
# интерфейс: http://127.0.0.1:8811/  ·  API: http://127.0.0.1:8811/docs
```

Пошаговая инструкция с системными зависимостями и проверкой — в корневом
[README](../README.md#как-развернуть-и-запустить).

Промпты и конфигурация — файлами: `skills/*.yaml` (загрузчик `app/skills.py`),
`../pptx_template_parser_generator/prompts/*.txt`, `.env`
(см. [MODELS.md](../MODELS.md)).


## API

Шаблон

- `POST /templates/analyze` (multipart: `template` — .pptx) — разбор шаблона:
  `DesignManifest` + Template JSON. Возвращает `template_analysis_id`.
- `GET /templates/{id}` — результат разбора.
- `GET /templates/{id}/design-system` — дизайн-система для интерфейса: цвета,
  гарнитуры, шкала типографики (все стили текста шаблона), карточки всех
  макетов с миниатюрами, источник дизайна (`design_source`,
  `design_source_info`) и распознанные композиции (`compositions`: вид,
  источник — образец/макет/библиотека, число, примеры).
- `PUT /templates/{id}/manifest` — ручные правки палитры/шрифтов.

Задача

- `POST /jobs` (multipart: `template` или `template_analysis_id`, `brief`,
  `purpose`, `slide_count`, опционально `slide_count_max` (диапазон «от–до»,
  модель выбирает число внутри), `content_plan` JSON, `case_prompt_addition`) —
  создаёт задачу, генерация в фоне.
- `GET /jobs/{job_id}` — статус и данные: `content_plan`, `variant_plans`
  (композиции по слайдам для A/B/C), `variant_kinds` (виды композиций по
  слайдам), `variant_descriptions`, `audit_issues`, `audit_stale`,
  `slide_edits`, `export_paths`.
- `GET /jobs/{job_id}/variants/{variant}/preview[/{n}]` — PNG-превью варианта
  (`variant_a|variant_b|variant_c`).
- `POST /jobs/{job_id}/select-variant` (JSON `{"variant": ...}`) — выбор варианта.
- `POST /jobs/{job_id}/audit` / `POST /jobs/{job_id}/skip-audit` — запустить
  или пропустить аудит выбранного варианта; `audit` допустим и из `done`
  (повторный аудит после доработки слайдов).
- `POST /jobs/{job_id}/variants/{variant}/slides/{index}/edit` (JSON
  `{"action": "recompose" | "rewrite" | "take_from", "source": "variant_a"}`) —
  точечная доработка одного слайда: другая композиция шаблона под тот же
  контент (история замен хранится в `slide_edits`, уже показанные не
  повторяются), переформулировка текста моделью или перенос слайда из другого
  варианта. Вариант пересобирается, превью обновляется, аудит помечается
  устаревшим (`audit_stale`).
- `POST /jobs/{job_id}/fix` (JSON `{"issue_ids": [...]}`) — пересборка и
  повторный аудит.
- `GET /jobs/{job_id}/variants/{variant}/audit-map` — карта аудита: фигуры
  слайдов с нормализованными рамками и привязанные замечания (`fixable`).
- `POST /jobs/{job_id}/fix-issues` (JSON `{"issue_ids": [...]}`) — точечное
  исправление замечаний в выбранном варианте + повторный аудит ([AUDIT.md](../AUDIT.md)).
- `GET /jobs/{job_id}/variants/{variant}/audit-overlay/{n}` — PNG слайда с
  рамками замечаний.
- `POST /jobs/{job_id}/slides/{slide_id}/import-excel`,
  `POST /jobs/{job_id}/slides/{slide_id}/content-block`, `POST /excel/sheets` —
  импорт таблиц/графиков из Excel.
- `GET /jobs/{job_id}/export?format=pptx|pdf|html&variant=...` — готовый файл.


## Пайплайн

```
Шаблон (.pptx) ─▶ Парсер ─▶ DesignManifest + Template JSON ─┐
                                                            ├─▶ Сборка A/B/C ─▶ Выбор ─▶ Аудит (опц.) ─▶ Экспорт
Бриф + назначение ─▶ Контент-агент ─▶ ContentPlan ──────────┤
                    Драматургия ─▶ structured + композиции ─┘
                    (запасной путь: планировщик макетов ─▶ layout_plan)
```

Статусы `Job`: `queued → parsing → planning → assembling →
awaiting_variant_choice → awaiting_audit_choice → auditing → done | failed`.

Дизайн берётся оттуда, где он есть в шаблоне: из макетов, из слайдов-образцов
(клонирование и адаптация блоков под число тезисов) или, если примеров нет,
из собственной библиотеки компоновок шрифтами и цветами шаблона
(`design_source`: `layouts` / `slides` / `mixed` / `library`). Три варианта
собираются по одному плану содержания и различаются плотностью подачи:
A — Лаконичный (до 4 блоков, только заголовки тезисов), B — Сбалансированный
(до 6 блоков, заголовок + пояснение), C — Насыщенный (до 8 блоков, развёрнутые
пояснения, заметки, фото) — и характером композиций: у каждого варианта свои
предпочтения (тезисы и метрики / карточки и таймлайны / фото и текст), а на
одном слайде варианты не берут одну и ту же композицию, если у шаблона есть
выбор. Графики стилизуются под фон слайда (светлый текст на тёмном фоне,
подписи данных), разделы получают лид и пункты раздела, а компоновки с большим
числом плашек под малое число тезисов не выбираются. Для шаблонов, где структурирование не удалось,
работает классический путь по макетам (A — одноколоночные, B — двухколоночные,
C — с фото и фактоидами). Подробности — [ARCHITECTURE.md](../ARCHITECTURE.md),
[MODELS.md](../MODELS.md), [AUDIT.md](../AUDIT.md).

## Ограничения текущей версии

- **Нет БД.** Job-стор — `dict` в памяти процесса (`app/job_store.py`). Рестарт
  backend теряет все задачи.
- **Нет очередей/воркеров.** Каждый job — это `asyncio.create_task` в том же
  процессе. Параллельная нагрузка ограничена ресурсами одного процесса;
  осознанное упрощение MVP под требование "монолит без Celery/Redis".
- **Классификация макетов через VLM не реализована** — `parser.classify_layouts_with_vlm`
  это `NotImplementedError`-заглушка. Сейчас все роли макета определяются
  только детерминированно по типам плейсхолдеров из XML.
- **VLM-аудит контента реализован, но не проверен вживую.**
  `audit.audit_content_with_vlm` работает и вызывается автоматически при
  сборке каждого варианта (управляется флагом `VLM_AUDIT_ENABLED` в
  `config.py`), но в текущей среде разработки нет доступа к реальному
  VLM-эндпоинту — подтверждена только graceful degradation (при
  недоступности VLM создаётся одна явная проблема на слайд вместо падения
  пайплайна). Подробности и полный список 11 вопросов — в
  [AUDIT.md](../AUDIT.md).
- **Старый движок синтетических паттернов** (`app/config/layout_patterns.yaml`,
  `pipeline/assembly.py`) в сборке не участвует и оставлен для совместимости
  `POST /jobs/{id}/fix`; текущие источники дизайна — макеты, слайды-образцы и
  библиотека компоновок (см. [ARCHITECTURE.md](../ARCHITECTURE.md)).
- **Shrink-to-fit заголовков.** Если заголовок не помещается в узкий слот,
  кегль уменьшается (не ниже 55 % исходного) вместо обрезки текста; это может
  дать замечание аудита «кегль вне шкалы шаблона».
- **`POST /jobs/{id}/fix` пересобирает всю колоду**, а не правит точечно;
  для избирательных исправлений (кегль, шрифт, цвет, длина тезисов и т.д.)
  используется `POST /jobs/{id}/fix-issues`. Замечания без автоисправления
  (VLM-контент, заполненность, размер таблиц) остаются на ручную правку.
- **Проверка контраста в аудите — best-effort.** Считается только когда и
  текст, и фон слайда имеют явно заданный `srgbClr` (не унаследованный из
  темы цвет) — иначе слайд молча пропускается, чтобы не давать ложных
  срабатываний. Порог зафиксирован на 4.5:1 согласно ТЗ.
- **Верхняя граница проверки заполненности слайда (аудит) откалибрована с
  75% (буквальный текст ТЗ) до 92%** — обоснование в [AUDIT.md](../AUDIT.md#отклонения-от-буквального-текста-тз-с-обоснованием).
- **CORS открыт на `*`.** Перед реальным (не хакатонным) деплоем нужно сузить
  `allow_origins` в `app/main.py`.
- **Превью и экспорт в pdf/html требуют LibreOffice** как внешнюю системную
  зависимость — она не ставится через `requirements.txt`. Запуски soffice
  сериализованы (`pipeline/soffice.py`): одновременная конвертация нескольких
  файлов на одном профиле роняла soffice с кодом 1. HTML-экспорт — автономная
  страница-слайдшоу со встроенными растрами слайдов (не редактируемая
  разметка): штатный HTML-фильтр LibreOffice падает на шаблонах с фото.
- **Планирование последовательное** (контент-агент → планировщик макетов),
  а не параллельное: так оба прохода описывают одни и те же слайды. Цена —
  ~20–30 с к общему времени; полный цикл до трёх вариантов ≈ 1,5–3 мин.
- **Только десктоп.** Интерфейс не адаптирован под мобильные экраны — по ТЗ.
