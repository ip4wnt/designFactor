# Аудит

Документ описывает пайплайн проверки готовой презентации: `app/pipeline/audit.py`.
Соответствует требованию ТЗ, раздел 4 («AUDIT — список тестов и их область
покрытия»), чек-лист построен на основе Приложения 1 официального ТЗ
(«Критерии качества и аудита»).

Аудит запускается автоматически после сборки каждого варианта верстки
(`orchestrator.py`, `_assemble_and_audit_one_variant`) и складывает найденные
проблемы в `Job.audit_issues[variant]`. Каждая проблема (`AuditIssue`) несёт
поле `deterministic: bool`, которое отличает детерминированную проверку от
модельной (VLM), и поле `category` (`layout` / `template` / `density` /
`integrity` / `content`).

## Детерминированные проверки (`audit_presentation`)

Работают напрямую с объектами `python-pptx` (+ опционально `DesignManifest`
шаблона), не вызывают никаких моделей — поэтому воспроизводимы: одинаковый
`.pptx` всегда даёт одинаковый результат.

### Вёрстка (`AuditCategory.LAYOUT`)

| Пункт Приложения 1 | Реализация | Примечание |
|---|---|---|
| Элемент вышел за границы слайда | `_check_bounds` | `left/top < 0` или `left+width/top+height > slide_size` |
| Текст обрезан краем слайда | `_check_bounds` | Объединено с проверкой выхода за границы — тот же геометрический признак |
| Два блока наложились друг на друга | `_check_overlap` | Попарное пересечение bounding box всех фигур на слайде |
| Текст не поместился в свою рамку | `_check_text_overflow` | Эвристика: оценка числа строк по символам на строку (из ширины рамки и среднего шрифта) против доступной высоты. Пропускает фигуры со включённым PowerPoint auto-fit (`normAutofit`/`spAutoFit`), т.к. там переполнение невозможно по построению |
| Контент заходит в поля у краёв | `_check_edge_margins` | Порог поля — 2% от размера слайда (`_EDGE_MARGIN_RATIO`). Крупные структурные блоки (>15% площади слайда, либо растянутые на ≥95% ширины/высоты — шапки, колонки с графиком/таблицей, фоновые подложки) исключены из проверки: у края почти всегда стоят намеренно, а не случайно. Флагуются только небольшие/средние фигуры |
| Картинка растянута, пропорции нарушены | `_check_image_aspect_ratio` | Сравнивает нативное пиксельное соотношение сторон изображения (из его бинарных данных) с соотношением сторон рамки на слайде; расхождение > 5% — проблема |
| Блоки не выровнены по направляющим макета | **Не реализовано** | См. раздел «Осознанно не реализовано» ниже |

### Шаблон (`AuditCategory.TEMPLATE`)

| Пункт Приложения 1 | Реализация | Примечание |
|---|---|---|
| Контраст текста к фону ниже 4.5:1 | `_check_contrast` | Порог **исправлен на 4.5:1** согласно тексту ТЗ (было ошибочно 3.0 — стандартный WCAG AA для крупного текста, а не общее требование ТЗ). Считается только когда и текст, и фон слайда имеют явный `srgbClr` — иначе пропускается (best-effort, чтобы не давать ложных срабатываний на цветах, унаследованных из темы) |
| Шрифт не из шаблона или гарнитур больше двух | `_check_template_conformance` | Требует передачи `DesignManifest`. Флагует шрифт, не входящий в `{manifest.title.font, manifest.body.font}`, и слайды с >2 различных гарнитур |
| Кегль не из типографической шкалы шаблона | `_check_template_conformance` | Кегль вне допуска ±0.5pt от `{manifest.title.size, manifest.body.size}` |
| Цвет не из палитры шаблона | `_check_template_conformance` | HEX цвета текста/заливки, не входящего в `manifest.palette` |
| Слайд собран не на макете из шаблона | **Не реализовано** (осознанно) | См. ниже |
| Логотип или колонтитул сдвинуты с положенного места | **Не реализовано** (осознанно) | См. ниже |

### Плотность (`AuditCategory.DENSITY`)

| Пункт Приложения 1 | Реализация | Примечание |
|---|---|---|
| Больше 6 буллетов на слайде | `_check_density` | Существовавшая проверка (без изменений) |
| Буллет длиннее 15 слов | `_check_density` | Существовавшая проверка (без изменений) |
| Таблица больше 7 строк или 5 колонок | `_check_table_size` | `shape.has_table`, считает `table.rows`/`table.columns` |
| Больше 5 серий на диаграмме | `_check_chart_series` | `shape.has_chart`, `chart.plots[0].series` |
| Слайд заполнен меньше четверти или больше трёх четвертей | `_check_fill_ratio` | Нижняя граница оставлена по ТЗ — **25%** (`_MIN_FILL_RATIO`). Верхняя граница **откалибрована с 75% (буквальный текст ТЗ) до 92%** (`_MAX_FILL_RATIO`) — см. «Отклонения от буквального текста ТЗ» ниже |

### Целостность (`AuditCategory.INTEGRITY`)

| Пункт Приложения 1 | Реализация | Примечание |
|---|---|---|
| Файл не открывается | `audit_presentation` (try/except вокруг `Presentation()`) | Возвращает единственную проблему уровня файла, не роняет пайплайн |
| Остался текст-заглушка (lorem ipsum, XXX, TODO, «вставьте текст») | `_check_placeholder_text` | Регулярка на набор паттернов + добавлен паттерн для типичных мета-комментариев модели («как ИИ-модель», «в данном примере» и т.п.) |
| Пустой слайд или слайд с одним заголовком | `_check_empty_slide` | 0 или 1 текстовая фигура с непустым текстом и отсутствие таблицы/графика/картинки |
| Слайд оказался картинкой, а не редактируемыми объектами | `_check_rasterized_slide` | Единственная фигура на слайде — картинка, нет других значимых элементов |
| У диаграммы нет подписей осей, единиц или легенды | `_check_chart_annotations` | Флагует диаграмму без легенды **и** без подписанных осей **и** без подписей данных одновременно |
| Два слайда дублируют друг друга | `_check_duplicate_slides` | Точное совпадение текстовой сигнатуры (конкатенация текста всех фигур) между слайдами |

## Недетерминированные проверки — «Валидация контента» (`audit_content_with_vlm`)

Раздел ТЗ «Валидация контента»: 11 вопросов да/нет, на вход — картинка слайда.
Выполняется моделью (vision-language model), поэтому на повторных запусках
может дать другой ответ — это ожидаемо и заложено в архитектуру ТЗ.

Рендер: `render_slides_to_png` конвертирует `.pptx` → `.pdf` через LibreOffice
(`export_presentation`), затем `.pdf` → PNG постранично через `pdftoppm -png -r 110`.
Один PNG на слайд.

Один VLM-вызов на слайд задаёт все 11 вопросов одновременно (единый
JSON-объект в ответе) — так один слайд стоит один вызов модели, а не 11.
Параллелизм ограничен `asyncio.Semaphore` (по умолчанию 3 одновременных
вызова), чтобы не перегружать VLM-эндпоинт на колоде из 10-15 слайдов.
Каждый ответ `"false"` на вопрос порождает `AuditIssue(deterministic=False,
category=CONTENT)`.

| № | Вопрос из Приложения 1 | Формулировка в коде | Причина переформулировки |
|---|---|---|---|
| 1 | Заголовок содержит вывод, а не просто называет тему? | Без изменений | — |
| 2 | Содержимое слайда соответствует заголовку? | Без изменений | — |
| 3 | Слайд пересказывается одним предложением? | Без изменений | — |
| 4 | Все цифры и факты со слайда есть в исходных материалах? | «Все цифры и факты со слайда выглядят взаимно согласованными (не противоречат друг другу)?» | Функция аудита получает на вход только изображение слайда, без доступа к исходному брифу/контент-пакету — сверить с «исходными материалами» технически невозможно на этом шаге пайплайна. Заменено на проверку внутренней непротиворечивости чисел на слайде |
| 5 | На слайде есть содержание, а не только заголовок? | Без изменений | Частично дублирует детерминированный `_check_empty_slide`, оставлено как перекрёстная проверка от VLM |
| 6 | Картинки и иконки относятся к теме слайда? | «...(если есть) относятся к теме слайда?» | Уточнение на случай отсутствия изображений на слайде |
| 7 | Нет служебного мусора: реплик спикера, кусков промпта? | Добавлено «технических артефактов» | Расширение формулировки, суть не изменена |
| 8 | Текст без опечаток? | Без изменений | — |
| 9 | Вся колода на одном языке? | «Текст на слайде на одном языке (без случайного смешения языков)?» | Вопрос по своей природе межслайдовый («вся колода»), но VLM-вызов в текущей архитектуре работает по одному слайду за раз без общего контекста колоды — переформулирован в проверку внутри одного слайда. Полноценная межслайдовая проверка требует отдельного прохода со всеми слайдами в одном контексте — см. «Известные ограничения» |
| 10 | Все строки таблицы и элементы легенды работают на мысль слайда? | «...(если есть)...» | Уточнение на случай отсутствия таблицы/легенды |
| 11 | Соседние слайды связаны между собой по логике? | «Слайд логично мог бы стоять в деловой презентации на заявленную тему?» | Требует контекста соседних слайдов, который не передаётся в текущий вызов (по одному слайду за раз) — заменено на проверку правдоподобия слайда как самостоятельной единицы. Полноценная реализация требует межслайдового контекста — см. «Известные ограничения» |

### Graceful degradation

Если VLM-эндпоинт недоступен (сетевая ошибка, таймаут, некорректный ответ),
`orchestrator._run_vlm_audit_safely` перехватывает исключение и не роняет
пайплайн: вместо 11 отдельных проблем на слайд создаётся ровно одна
`AuditIssue(deterministic=False, category=CONTENT)` с текстом «VLM-проверка
контента не выполнена: <причина>». Остальные варианты и остальной аудит
(детерминированный) отрабатывают штатно. Управляется флагом
`VLM_AUDIT_ENABLED` в `config.py` (по умолчанию `True`) — при `False`
VLM-аудит не запускается вовсе и не появляется в списке проблем.

## Отклонения от буквального текста ТЗ (с обоснованием)

- **Контраст 4.5:1** — ТЗ прямо требует именно это значение (раздел
  «Шаблон»). Ранее в коде было ошибочно 3.0 (WCAG AA для крупного текста) —
  исправлено на 4.5.
- **Верхняя граница заполненности слайда — 92%, а не буквальные «три
  четверти» (75%) из ТЗ.** При тестировании на реальном шаблоне (`presentation-11.pptx`,
  тёплая золотисто-кремовая тема) слайды с двумя штатными полноширинными
  блоками (заголовок + текст, или заголовок + таблица) легитимно занимают
  94–96% площади слайда — это нормальная, предусмотренная шаблоном
  верстка, а не переполнение. Порог 75% на такой колоде массово ложно
  срабатывал бы на каждом «нормальном» слайде. Порог поднят эмпирически до
  92%, при этом нижняя граница (25%, «слайд заполнен меньше четверти»)
  оставлена без изменений — недозаполненность в ходе тестов не наблюдалась
  ложноположительной.
- **Проверка «контент заходит в поля у краёв» пропускает крупные
  структурные блоки.** Буквальное прочтение («любой контент ближе 2% к
  краю — проблема») массово флагует легитимные full-bleed элементы
  шаблонов: шапки на всю ширину, колонки с графиком/таблицей, доходящие до
  нижнего края. Правило сужено: репортятся только небольшие/средние фигуры
  (≤15% площади слайда и не растянутые на ≥95% ширины/высоты), у которых
  примыкание к краю с высокой вероятностью — случайный сдвиг, а не
  осознанная композиция.

## Осознанно не реализовано (scoping-решения)

Приложение 1 явно называет себя «расширяемым ориентиром», который можно
«расширять и сокращать с обоснованием». Два пункта не реализованы как
отдельные проверки для текущей генеративной (paceless/placeholder-free)
архитектуры вёрстки:

- **«Слайд собран не на макете из шаблона».** В использованной архитектуре
  (см. `docs/ARCHITECTURE.md`) Компоновщик не привязывает слайд к
  конкретному XML-макету (`slideLayout`) шаблона — вместо этого он
  генеративно расставляет фигуры по одному из ~15-20 паттернов вёрстки
  (отдельный YAML-конфиг), используя токены дизайн-системы (шрифты, цвета,
  стили таблиц/графиков), извлечённые Парсером. Слайды не «собираются на
  макете» в буквальном смысле PowerPoint layout — поэтому сам вопрос «на
  каком макете собран слайд» неприменим к этой архитектуре. Соответствие
  дизайн-системе шаблона проверяется по существу через
  `_check_template_conformance` (шрифты/кегли/цвета).
- **«Логотип или колонтитул сдвинуты с положенного места».** По той же
  причине: генеративная вёрстка не оперирует понятием фиксированного
  «положенного места» логотипа/колонтитула, унаследованного из
  конкретного `slideLayout`/`slideMaster` шаблона в неизменном виде для
  каждого нового слайда. Если в будущей версии Компоновщик начнёт явно
  переносить фигуры-логотипы с постоянной геометрией из мастер-слайда
  шаблона, эта проверка станет осмысленной и её стоит добавить.

## Известные ограничения

- **VLM-аудит не проверялся вживую с реальным VLM-эндпоинтом.** Локальная
  среда разработки не имеет доступа к `VLM_BASE_URL`
  (`http://localhost:11434/v1` по умолчанию, Ollama-style) — только
  graceful degradation подтверждён тестом (корректно генерирует одну
  проблему на слайд с сообщением об ошибке, не роняет пайплайн). Реальное
  качество ответов VLM на 11 вопросов не оценивалось.
- **Вопросы 9 и 11 переформулированы под однослайдовый вызов** (см. таблицу
  выше) и не выполняют буквально то, что описано в ТЗ («вся колода на
  одном языке», «соседние слайды связаны по логике»). Полноценная
  реализация требует отдельного межслайдового VLM-вызова (например, один
  вызов с изображениями всех слайдов колоды сразу, или последовательные
  вызовы с передачей краткого резюме предыдущих слайдов) — не реализовано
  в этой фазе.
- **`_check_text_overflow` — эвристика, не точный рендер.** Оценка числа
  строк идёт по среднему количеству символов на строку, а не по реальному
  тексто-рендерингу шрифта — на редких гарнитурах с нестандартной шириной
  символов возможны как ложные срабатывания, так и пропуски.
- **`_check_fill_ratio` суммирует площади bounding box без учёта
  взаимных пересечений фигур** — если несколько фигур накладываются друг
  на друга, их площади всё равно складываются, из-за чего оценка
  заполненности может быть завышена относительно фактически видимой
  площади. Для целей данной проверки (грубая оценка «слайд пуст» /
  «слайд перегружен») это признано достаточным.
